# Questions for Library Technical Staff

## Primo / catalog

- Is there an approved Primo API endpoint for ZSR discovery search?
- Is API access available for article discovery, catalog records, holdings, availability, and thumbnails?
- Are there rate limits or authentication requirements?
- Is there a preferred way to deep-link to records and searches?

## A-Z Databases / LibGuides

- Can ZSR export or provide structured metadata for A-Z Databases?
- Can each database include subject, description, access notes, best-for, and search URL metadata?
- Who should own ongoing maintenance of the database recommendation config?

## Full text / LibKey

- Does ZSR have a preferred LibKey Nomad help page?
- Is Wake Forest's LibKey / Third Iron library ID available for DOI/PMID lookups?
- Is there an approved LibKey API path, or should the prototype stay with extension guidance and link-outs?

## Citation help

- What are the official ZSR URLs for APA, MLA, Chicago, Zotero, and general citation help?
- Should citation help point to ZSR pages, LibGuides pages, Zotero pages, or all of them?

## Hosting and security

- Should this remain externally hosted for prototype review, or should a Wake Forest-owned environment host it?
- What security review is needed before students use it?
- Are there branding rules for using ZSR/Wake Forest names and imagery?
- What rate limits or abuse protections would be expected?

## AI governance

- Are Gemini/OpenAI/Anthropic APIs acceptable for this type of research assistant?
- What model/provider review is required?
- What disclaimers or responsible-use language should appear in the UI?
- Should prompts/responses be retained, redacted, or discarded?

## Success criteria

- What would make this useful enough for a small pilot?
- What accuracy bar should database recommendations meet?
- Which 3-5 subject areas should be tested first?
- Who should review the first librarian-approved resource config?
