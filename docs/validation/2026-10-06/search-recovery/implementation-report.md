# Empty-result recovery and source images — October 6, 2026

## Implemented

- A single empty-result panel explains whether the providers returned no records, returned records that failed topic/assignment checks, could not complete the request, or were not connected. None of these states claims relevant literature does not exist.
- Clear next actions: retry a temporary failure with the same requirements; use an untried synonym expansion when available; edit search terms; review requirements; search ZSR or Google Scholar directly; contact a ZSR librarian. External links carry topic terms; the interface explicitly asks students to apply assignment filters in the destination tool.
- Bold emphasis distinguishes the result status, next actions, requirement caveats, and the instruction to verify AI claims. Detailed queries and preserved requirements remain collapsed.
- After completed empty searches, discovery tries at most two additional equivalent/keyword queries within the existing time budget. Keyword recovery relaxes inferred short phrase adjacency, retains every word and all facets, and leaves explicitly quoted phrases and known-item titles intact. Relevance and assignment checks still apply.
- Provider diagnostics include the actual attempted query, page-level retrieved count, eligible count, and empty reason. Counts from different requests are not summed as distinct publications. Malformed payloads report errors; malformed individual Primo rows no longer discard valid neighbors.
- Source cards render supplied article/publication thumbnails and ISBN-matched book covers. Labels distinguish source images from book covers. Covers may depict the containing book/journal. Missing, broken, or tiny placeholder images fall back to a document icon. Images load lazily and do not send the page referrer. No image is invented from a title or generated by AI.

Provider responses and timing vary; these small changes do not establish a causal or statistically significant improvement. Three narrow topics still returned no eligible records. The open-access-only case could not search because OpenAlex has no configured key. The updated interface reports that connection problem; this work does not provision a key.

**This is availability evidence, not an accuracy score.** No human relevance judgments or full-text claim-support review were added. AI guidance can hallucinate claims or misground them in real sources. Provider metadata, fit labels, and cover matching can also be imperfect. Source accuracy and usefulness must still be assessed with students and librarians.
